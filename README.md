# Coachin

**An AI fitness coach you can talk to.** Coachin builds personalized training programs,
tracks your workouts and meals, suggests your next weights with progressive overload,
writes monthly progress reports with charts, and screens every message for medical
red flags.

Built with FastAPI, Streamlit, PostgreSQL, OpenAI (GPT-4o, Whisper, TTS) and Pinecone;
deployed on AWS EC2 with Docker and GitHub Actions.

[![CI](https://github.com/AmerKone/Coachin/actions/workflows/ci.yml/badge.svg)](https://github.com/AmerKone/Coachin/actions/workflows/ci.yml)
[![Deploy](https://github.com/AmerKone/Coachin/actions/workflows/deploy.yml/badge.svg)](https://github.com/AmerKone/Coachin/actions/workflows/deploy.yml)

> **Not medical advice.** Coachin gives general fitness guidance. It is not a substitute for a
> doctor, physiotherapist or dietitian.

## Features

| | |
|---|---|
| 🎙️ **Voice coach** | Talk or type. The coach answers with context from your profile, program, logs and a curated knowledge base, and can act for you: log a set, log a meal, record your weight, swap an exercise, look up any past workout or PR. |
| 🗓️ **Personalized programs** | Multi-week plans generated by the LLM from a 102-exercise library, restricted to your equipment, adapted to your injuries, with weekly progression and deload weeks. |
| 🏋️ **Progressive overload** | Log sets against targets; the next session's weight and reps are suggested with double progression, with a plain-English reason. |
| 🍽️ **Nutrition tracking** | Describe a meal in words; get an item-by-item estimate to review and save. Daily targets are computed from your profile. |
| 📈 **Progress reports** | Weight, strength, calorie and training-volume curves for any month or the last 3/12 months, plus an AI-written monthly report. |
| 🩺 **Safety guardrails** | Emergency symptoms, injuries, disordered eating and drug questions get fixed, pre-written responses; unsafe advice (e.g. under 1,200 kcal/day) is blocked. |

## Architecture

```
Streamlit frontend ──HTTP/JSON + JWT──▶ FastAPI backend ──▶ PostgreSQL (all user data)
  (pages, mic, charts)                  routes → services     ├──▶ OpenAI (chat, structured
                                        → agent + tools        │     outputs, embeddings,
                                        → RAG retrieval        │     Whisper, TTS)
                                                               └──▶ Pinecone (knowledge base)
```

- **Frontend** (`frontend/`): Streamlit multipage app; talks to the backend only through its API.
- **Backend** (`backend/app/`): FastAPI routes → services → SQLAlchemy models; the coach agent
  and its tools live in `agent/`, retrieval in `rag/`.
- **Knowledge base** (`knowledge_base/`): Markdown documents (training, nutrition, safety)
  embedded into Pinecone and retrieved to ground the AI's answers.

## Getting started

You need an [OpenAI API key](https://platform.openai.com/api-keys) and a
[Pinecone API key](https://app.pinecone.io) (the free Pinecone plan is enough).

### Option A: Docker (recommended)

Requires [Docker Desktop](https://www.docker.com/products/docker-desktop/) (or Docker Engine
with Compose).

```bash
git clone https://github.com/AmerKone/Coachin.git
cd Coachin
cp .env.example .env            # then set OPENAI_API_KEY, PINECONE_API_KEY, JWT_SECRET_KEY
docker compose up --build       # first build takes a few minutes
```

Open **http://localhost:8501** (API docs: http://localhost:8000/docs). This starts three
containers: PostgreSQL, the FastAPI backend and the Streamlit frontend. On startup the backend
creates the tables and loads the exercise library automatically; your data persists in a
Docker volume.

Load the knowledge base into Pinecone once (skip it if your index is already populated):

```bash
docker compose exec backend python scripts/ingest_knowledge.py
```

| Command | What it does |
|---|---|
| `docker compose up -d` | Start in the background |
| `docker compose logs -f backend` | Follow the backend logs |
| `docker compose down` | Stop (data is kept) |
| `docker compose down -v` | Stop and **delete** the database volume |

Ports can be changed in `.env` with `FRONTEND_PORT`, `BACKEND_PORT` and `DB_PORT` (the
database is exposed on `localhost:5433` by default, to avoid clashing with a local PostgreSQL).

### Option B: Local Python

#### Prerequisites

- Python 3.11 or newer
- PostgreSQL (tested with 18)

#### 1. Install

```bash
git clone https://github.com/AmerKone/Coachin.git
cd Coachin
python -m venv .venv
.venv\Scripts\activate          # Windows  (macOS/Linux: source .venv/bin/activate)
pip install -r backend/requirements.txt -r frontend/requirements.txt
```

#### 2. Configure

Create the database and a user for it (you'll be asked for the `postgres` password):

```bash
psql -U postgres -c "CREATE ROLE coachin WITH LOGIN PASSWORD 'coachin';" -c "CREATE DATABASE coachin OWNER coachin;"
```

Copy the environment template and fill in your keys:

```bash
cp .env.example .env            # Windows PowerShell: Copy-Item .env.example .env
```

| Variable | What to put |
|---|---|
| `OPENAI_API_KEY` | Your OpenAI key |
| `PINECONE_API_KEY` | Your Pinecone key (the index is created automatically) |
| `DATABASE_URL` | Keep the default if you used the commands above |
| `JWT_SECRET_KEY` | Any long random string |

#### 3. Set up the data

```bash
python scripts/init_db.py            # create the tables
python scripts/seed_exercises.py     # load the 102-exercise library
python scripts/ingest_knowledge.py   # embed the knowledge base into Pinecone
```

#### 4. Run

In two terminals (with the virtual environment activated):

```bash
uvicorn app.main:app --reload --app-dir backend   # API: http://localhost:8000/docs
streamlit run frontend/app.py                      # App: http://localhost:8501
```

## Deployment

Coachin runs in production on a single **AWS EC2** instance with Docker Compose, and every
push to `main` is tested and deployed automatically by **GitHub Actions**.

```
push to main ──▶ CI: tests against PostgreSQL
                   └─(pass)─▶ Deploy: build images ──▶ GitHub Container Registry
                                        └──▶ SSH to EC2 ──▶ docker compose pull && up -d

Users ──HTTPS──▶ Caddy (Let's Encrypt) ──▶ Streamlit ──▶ FastAPI ──▶ PostgreSQL
```

| Piece | File | Role |
|---|---|---|
| CI | [`.github/workflows/ci.yml`](.github/workflows/ci.yml) | Runs the test suite against a PostgreSQL service on every push and pull request |
| CD | [`.github/workflows/deploy.yml`](.github/workflows/deploy.yml) | After CI passes on `main`: builds both images (cached), pushes them to GHCR, then updates the server over SSH |
| Production stack | [`deploy/docker-compose.prod.yml`](deploy/docker-compose.prod.yml) | PostgreSQL, backend, frontend and Caddy; only Caddy is public (ports 80/443) |
| HTTPS | [`deploy/Caddyfile`](deploy/Caddyfile) | Automatic certificates for `$DOMAIN`. HTTPS is required for the browser microphone. |

### Setting up your own server

1. **Launch an EC2 instance:** Ubuntu 24.04, `t3.small` (2 GB RAM), 20 GB disk. Allow inbound
   SSH (22), HTTP (80) and HTTPS (443) only, and attach an **Elastic IP**.
2. **Point a domain** at the Elastic IP (a free [DuckDNS](https://www.duckdns.org) subdomain works).
3. **Prepare the server:** install Docker (`curl -fsSL https://get.docker.com | sudo sh`), add a
   2 GB swap file, clone the repository (with a read-only deploy key if it's private), and run
   `docker login ghcr.io` with a token that has only the `read:packages` scope.
4. **Create `~/Coachin/.env` on the server** from `.env.example`: your OpenAI and Pinecone keys,
   a **new** `JWT_SECRET_KEY` (`openssl rand -hex 32`), plus `POSTGRES_PASSWORD` and `DOMAIN`.
   This file never leaves the server.
5. **Add repository secrets** (Settings → Secrets and variables → Actions): `EC2_HOST`,
   `EC2_USER` (`ubuntu`) and `EC2_SSH_KEY`, the private half of a key pair used only for
   deployments, whose public half is in the server's `~/.ssh/authorized_keys`.
6. **Allow image publishing:** Settings → Actions → General → Workflow permissions →
   *Read and write*.
7. **Push to `main`.** CI runs, then Deploy builds, publishes and starts the stack. The site
   is live at `https://<your-domain>` (the first certificate takes up to a minute).

### Operating the server

Run on the server from `~/Coachin` (define the alias once:
`alias prod='docker compose --env-file .env -f deploy/docker-compose.prod.yml'`):

| Task | Command |
|---|---|
| Status and health | `prod ps` |
| Follow logs | `prod logs -f caddy backend` |
| Back up the database | `prod exec -T db pg_dump -U coachin coachin > backup.sql` |
| List users | `prod exec db psql -U coachin -d coachin -c "SELECT email, created_at FROM users;"` |
| Deploy manually | `git pull && prod pull && prod up -d` |

**Pausing to save costs:** disable the *Deploy* workflow in the Actions tab, then stop the
instance (data is kept on the disk). To pay almost nothing while it's unused, create an AMI of
the stopped instance, then terminate it and release the Elastic IP. Relaunch from the AMI later
and update the domain and the `EC2_HOST` secret with the new IP.

**Cost safety:** set an AWS budget alert and an OpenAI monthly usage limit. Anyone who signs
up on a public deployment uses your OpenAI credits.

## Project structure

```
backend/
  app/
    api/routes/     FastAPI endpoints (auth, users, exercises, programs, workouts,
                    nutrition, progress, chat, voice, safety)
    agent/          coach agent: prompts, tool loop, action and history tools

    schemas/        Pydantic request/response models
  data/             exercise library (JSON)
  tests/            pytest suite
frontend/
  app.py            home page
  pages/            Coach, Program, Workouts, Nutrition, Progress, Profile
  components/       auth, charts, voice, safety widgets
  client/           HTTP client for the backend API
knowledge_base/     training, nutrition and safety documents for RAG
scripts/            setup and seeding scripts
deploy/             production compose file and Caddy config
.github/workflows/  CI (tests) and CD (build, publish, deploy to EC2)
docker-compose.yml  local Docker stack
```

## Running the tests

```bash
cd backend
pytest
```

Tests use fakes for OpenAI, Pinecone and audio, so they cost nothing. Each database test runs
in a transaction that is rolled back, so no test data is left behind. Set `TEST_DATABASE_URL`
in `.env` to run them against a separate database.
